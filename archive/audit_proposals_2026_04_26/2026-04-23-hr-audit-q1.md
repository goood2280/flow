## 관찰 1 — eval-lead 유령 참조 (구조 불일치)

**관찰된 사실:**
`orchestrator.md` 37번 줄: "HR/mgmt-lead/eval-lead/reporter 는 존재하지 않는다 (슬림화 2026-04-19)".
그러나 다음 에이전트들의 협업 프로토콜에 `eval-lead` 가 호출자로 명시돼 있다:
- `dev-verifier.md` 19~20번 줄, 40·45번 줄
- `user-role-tester.md` 19·22·43·49번 줄
- `admin-role-tester.md` 16·19~21·41·48번 줄
- `security-auditor.md` 20~23·46·52번 줄
- `ux-reviewer.md` 20·36·41번 줄
- `domain-researcher.md` 19·21~22번 줄

6개 에이전트 전부에서 존재하지 않는 `eval-lead` 를 호출자/에스컬레이션 대상으로 참조 중이다.
실제 운용 시 orchestrator 가 직접 이들을 호출하게 되어, 에스컬레이션 경로 기술이 혼란을 유발할 수 있다.

**제안:**
6개 에이전트의 협업 프로토콜 내 `eval-lead` 참조를 `orchestrator` 로 일괄 교체.
구체적 delta 예시 (dev-verifier):
- 현행: "호출자는 eval-lead. 결과는 eval-lead에게만 반환."
- 변경안: "호출자는 orchestrator. 결과는 orchestrator에게만 반환."

**근거:**
orchestrator 공식 정의와 하위 에이전트 정의 사이 참조 불일치. 2026-04-22 HR Audit R1/R2 긴급 fix 에서 dev-lead 의 be-*/fe-* 참조 제거는 이미 반영됐으나, eval-lead 참조 제거는 미반영 상태.

**영향:** 6개 에이전트 md 파일 수정 필요. 기능 동작에는 영향 없고 문서 정합성 이슈.

**협의 필요 대상:** orchestrator, dev-lead (변경 수행자)

## 관찰 2 — dev-lead 활동 태그 에 long-format/smoke 누락

**관찰된 사실:**
`dev-lead.md` 38번 줄의 활동 태그 목록:
`dashboard · spc · ml · wafer-map · tablemap · ettime · tracker · filebrowser · admin · messages`

v8.8.29~v8.8.32 에서 두 개의 실질적인 신규 구성요소가 추가됐다:
- `core/long_pivot.py` — FAB datalake long-format 어댑터 (item_id/subitem_id/value/time → wide pivot)
- `scripts/smoke_test.py` — 27-test 공식 smoke suite

`splittable.py` 라우터 892~931번 줄 및 1759번 줄에서 `core.long_pivot` 을 실제로 import·호출하고 있음이 확인됐다. `dashboard.py` 에는 아직 long_pivot 참조가 없음.

**제안:**
`dev-lead.md` 활동 태그에 `long-pivot` (어댑터 계층)과 `smoke` (테스트 인프라) 추가.
태그 라인 변경안:
```
dashboard · spc · ml · wafer-map · tablemap · ettime · tracker · filebrowser · admin · messages · long-pivot · smoke
```

**근거:**
태그가 활동 로그 분류 기준이므로 실제 작업 영역과 불일치하면 viewer 분류가 정확하지 않다.

**영향:** `dev-lead.md` 1줄 수정. 기능 영향 없음.

**협의 필요 대상:** orchestrator

## 관찰 3 — dev-verifier 에 smoke_test.py 활용 미언급

**관찰된 사실:**
`dev-verifier.md` 는 curl 기반 검증만 기술하고 있다.
v8.8.32 시점에서 `scripts/smoke_test.py` (27 tests, stdlib urllib만 사용, exit code 0/1) 가 공식 smoke suite 로 존재한다.
dev-verifier 가 이 스크립트를 사전에 실행하면 기본 경로 검증 시간을 단축할 수 있다.

**제안:**
`dev-verifier.md` 의 주요 책임 또는 작업 흐름에 아래 문구 추가 (제안):
"릴리즈 검증 첫 단계로 `python scripts/smoke_test.py` 를 실행해 27개 핵심 경로 PASS/FAIL 를 먼저 확인한다. FAIL 항목은 curl 심층 재현으로 이어간다."

**근거:**
smoke_test.py 가 이미 admin·splittable·informs·meetings·tracker 경로를 포함하고 있어 dev-verifier 의 반복 curl 작업 일부를 자동화할 수 있다.

**영향:** `dev-verifier.md` 주요 책임 섹션 1항 추가. 기능 영향 없음.

**협의 필요 대상:** orchestrator

## 관찰 4 — "adapter-engineer" 에이전트 없음 (예상 대비 실제)

**관찰된 사실:**
이번 점검 요청에서 "adapter-engineer 가 long-format 스키마 자문에 맞게 업데이트돼있는가"를 확인하도록 지시했으나, `.claude/agents/` 에 `adapter-engineer` 에이전트는 존재하지 않는다.
`dev-lead.md` 와 `orchestrator.md` 는 어댑터 지식을 `OmniHarness/projects/fabcanvas/knowledge/adapter_mapping_rules.md` 문서 참조로만 처리한다.

**제안:**
현 구조(dev-lead 단일 풀스택 + knowledge md 참조)가 의도적 설계임을 확인. 별도 `adapter-engineer` 에이전트 신설은 현재 불필요하다고 판단.
단, `dev-lead.md` 의 knowledge 참조 목록에 `long_pivot.py` 경로(코드 참조)를 추가하는 scope-adjust 는 검토 가능.

**근거:**
`long_pivot.py` 는 이미 `splittable.py` 에서 직접 import 하고 있으며, 도메인 자문 역할이 아닌 어댑터 코드 역할이다. 별도 에이전트화할 만한 조사/자문 업무량이 관찰되지 않는다.

**영향:** 없음 (현상 유지 권고).

**협의 필요 대상:** orchestrator (현상 유지 확인 용)
