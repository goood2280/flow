## 항목 3 — dev-wafer-map / dev-ettime / dev-spc 비활성 상태 점검

**관찰:**

- `backend/routers/` 에 `wafer_map.py` 파일 없음. `frontend/src/pages/` 에 `My_WaferMap.jsx` 없음. v9.0.0 전후로도 생성 기록 없음.
- `frontend/src/pages/` 에 `My_ETTime.jsx`, `My_SPC.jsx` 모두 없음. 백엔드 `ettime.py`, `spc.py` 파일도 `backend/routers/` 목록에 없음.
- v9_roadmap.md 어디에도 ETTime, SPC, WaferMap 작업 언급 없음.
- 세 에이전트 모두 description 에 "없으면 신규 생성" 조건 포함 — 실제 대응 파일이 없는 상태에서 에이전트만 존재.
- 세 에이전트 합산 비용: 3개 × sonnet 모델 호출 비용 (발동 시).

**제안:**

세 에이전트에 대해 다음 중 하나를 orchestrator가 협의 후 결정할 것을 요청한다.

- 안 A: **dormant 표시** — description 서두에 "현재 대응 파일 없음. 신규 구축 지시 시에만 활성화" 추가. 모델 유지.
- 안 B: **제거** — 세 에이전트 파일 삭제. 해당 도메인 신규 구축 시 dev-lead 가 임시 처리하다가 hr 경유 재신설.
- 안 C: **모델 하향 + dormant** — 안 A 에 더해 sonnet → haiku 하향. 단순 조회·템플릿 생성 성격이 주이므로 reasoning 비중 낮음으로 추정.

HR 관찰 기준으로는 현재 3개 에이전트가 실코드 파일 없이 "신규 생성 의도"만 정의된 상태이므로, 안 B(제거) 또는 안 C(dormant + 하향)가 구성 단순화 면에서 유리하다고 판단한다. 결정은 dev-lead, eval-lead, orchestrator 3자 협의를 거친다.

**영향:** dev-lead 의 팀 구성 기술 업데이트 필요(해당 에이전트 제거 시).

**협의 필요 대상:** dev-lead, eval-lead, orchestrator
