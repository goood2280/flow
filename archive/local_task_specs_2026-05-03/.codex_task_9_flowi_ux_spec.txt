flow 앱(/mnt/d/TEST_Making_Video/semi_all/flow)의 홈 Flowi 응답 UX 두 가지 핵심 버그를 fix해. admin/일반 동일 UX.

[현 문제]
1. Flowi 응답이 결과(SplitTable / 차트 / lot list 등)를 채팅 흐름 안에 인라인으로 안 보여주고, 'SplitTable 열기' 같은 페이지 navigate 링크만 나오고 끝남. 사용자가 "A1001 plan 세운거 잘못된거 보여줘"라고 물어도 결과는 navigate 해야만 보임.
2. missing 필드 보완용 1/2/3 선택지가 응답 카드 위쪽에 작게 나오고 클릭이 명확하지 않다. 자연스럽게 응답 흐름의 맨 아래에 배치되고, 명확한 button 으로 클릭만 하면 곧장 ask 호출돼야 한다. free-input 텍스트박스도 같이.
3. admin 한정 분기로 동작 다르게 그리는 곳이 있으면 일반 유저와 동일하게 정렬한다(디버그 필드 redact 는 유지하되 결과/선택지 UX 동일).

[현 코드 reference]
- frontend/src/pages/My_Home.jsx
  * FlowiConsole, FlowiResult 컴포넌트
  * onChoice / onNavigate / ask
  * arguments_choices, missing, blocked, reject_reason 처리
- backend/routers/llm.py
  * /api/llm/flowi/chat 응답 shape: {tool, llm, prompt, selected_function, arguments_choices, missing, blocked, ...}
  * tool.type 후보: "table" | "chart" | "split_view" | "lot_list" | "navigate" | "message" 등 (실제 코드 확인 필요)
  * task #2 의 register_inform_walkthrough / Q1~Q8 응답 흐름
  * task #5 의 build_dashboard_metric_chart + chart_session_id 응답 흐름

[작업]

A) Flowi 응답 인라인 렌더 (admin/일반 동일)
   ★ frontend/src/pages/My_Home.jsx 의 FlowiResult 컴포넌트.
   - tool.type 별 인라인 렌더:
     * "table" 또는 SplitTable 데이터: 표 컴포넌트로 채팅 흐름 안에 직접 그림. 폭은 카드 폭 + overflow-x:auto. 행 수 많으면 max-height 320px + 내부 스크롤. SplitTable 캡처 형식(첫 헤더 cell 라벨만, wafer 한 행, KNOB/MASK 색상 강조) 그대로 적용.
     * "chart": task #5 의 multi-db-chart 응답을 인라인 차트 컴포넌트로 렌더. dashboard 의 차트 라이브러리 재사용.
     * "lot_list": lot 카드 list (root_lot/fab_lot/wafer/current_step) 인라인.
     * "split_view": SplitTable 일부 cell 들을 인라인으로(row x N wafer). 전체화면이 필요한 경우만 액션 버튼.
     * "message": 단순 텍스트 마크다운 렌더.
   - 결과 카드 헤더 우측에 작은 액션 버튼들 — "전체화면 SplitTable", "차트 페이지", "엑셀 내보내기" 등. 사용자가 navigate 원하면 누르고, 안 누르면 인라인으로만 보임.
   - 결과가 비었거나 missing 으로 데이터 못 받았을 땐 친근 한국어 안내 + 아래 choices.
   - admin 만 보였던 디버그 정보(intent, model, ctx, live_trace) 는 기존 정책대로 admin 만. 그 외 결과/UX 는 admin/일반 동일.

B) arguments_choices 위치 + 클릭 UX
   ★ FlowiResult 응답 카드의 가장 아래에 choices 영역.
   - missing 필드별로 작은 sub-section. 각 sub-section 헤더: "어느 모듈인가요?" 같은 친근 한국어 한 줄.
   - 선택지: 1/2/3 button(라디오 X). 버튼 스타일: 배경 #2a2a2a, hover #3a3a3a, accent border #f97316. 폰트 14, padding 8x12.
   - 버튼 클릭 시 prompt + " " + value 로 즉시 ask() 호출(현재 라디오 + 선택 동작 그대로 유지하되 button 으로 변경).
   - 마지막에 "또는 직접 입력해 주세요" 한 줄 + free-input 텍스트박스 + 보내기 버튼(Enter 도 동일).
   - free-input 으로 답하면 그 텍스트가 prompt 에 추가돼 ask() 호출.
   - admin 한정 분기로 choices UX 다르게 그리는 코드 있으면 제거 — 동일 UX.

C) 응답 카드 시각 정돈
