[배경 — 사용자 의도]
- 인폼은 도메인 관리자(lot 관리팀, 모듈팀)가 매일 보는 페이지. 적응 시간 0이 핵심.
- 현재 화면이 폼/카드/모달/이력/댓글이 한 화면에 섞여서 어디부터 봐야 할지 모호하다.
- 모듈 wise 메일(task #1), Q6/Q7/Q8 자연어 등록(task #2)이 추가됐지만 페이지 UX가 그 흐름을 깔끔히 흡수하지 못함.
- 정보 위계: ① 모듈별 progress 요약 → ② 인폼 list(필터/검색) → ③ 선택한 인폼의 detail(탭)로 자연스럽게 좁아져야.

[현 코드 reference — codex 가 작업 시작 전 먼저 read]

- 신규 endpoint (이미 있음 또는 task #1 으로 추가됨):
  * /api/informs/, /api/informs/{id}, /api/informs/{id}/send-mail, /api/informs/{id}/mail-preview
  * /api/informs/modules/recipients, /api/informs/modules/knob-map

[목표 — 3-pane 구조]

A) 좌측 column 1 (요약 + list, 폭 360px)
   1) 상단 카드: "모듈별 진행 요약" — 모듈 list(GATE/STI/PC/MOL/BEOL/ET/EDS/S-D Epi/Spacer/Well/기타) 각각 받음/완료 카운트 + 미완료 비율 작은 progress bar.
      - GET /api/informs/modules/summary (없으면 신규) → [{module, received, completed, in_progress, pending}]
      - 카드 클릭 시 우측 list 가 그 모듈로 필터.
   2) 하단: 인폼 list — 필터(모듈, 상태, product, root_lot, fab_lot, 작성자, 기간) + 검색창. virtualized scroll.
   3) 인폼 row: 작은 카드 — 제목 한 줄 / 모듈 pill + 상태 pill + 작성자 + 시간 / 메일 발송 여부 ✉️ 아이콘.
   4) 좌측 상단 우측에 + 버튼 — 신규 등록 wizard 시작.

B) 우측 column 2 (선택한 인폼 detail, 폭 flex)
   - 빈 상태: "왼쪽에서 인폼을 선택하면 자세한 내용이 여기 표시돼요" 안내.
   - 인폼 선택 시 상단 헤더(제목 + 모듈 + 상태 + lot pills + 액션 버튼들).
   - 본문 영역은 탭으로 분리:
     * 본문 — 사유/내용/SplitTable 캡처
     * 메일 — 수신자 미리보기/제목/본문/발송 이력
     * 댓글 — 답글 timeline
     * 이력 — 상태 변경/체크/수정 audit
     * 첨부 — 이미지/파일

C) 신규 등록 wizard (기존 한 폼 → 5 step)
   1. lot 선택 — product/root_lot_id/fab_lot_id (이미 있는 LotCombobox 재사용).
   2. 모듈 + 사유 — 모듈 dropdown(필수) + 사유 select + note free-input.
   3. SplitTable 첨부 — '자동 첨부 / CUSTOM 검색 후 첨부 / 안 함' 토글 (기존 v9.0.2 흐름 유지).
   4. 메일 미리보기 — task #1 의 자동 제목/본문/수신자 + KNOB 강조. 사용자 직접 편집 가능.
   5. 검토 + 등록 — 위 4 step 결과 한 화면 요약 + 등록 버튼. 등록 후 list 갱신.
   - "다음 / 이전" 버튼으로 step 이동. step 별 필수 누락 시 친근 한국어 경고("module 을 선택해 주세요").
   - 사용자가 wizard 중간에 닫아도 draft 자동 저장(localStorage), 다시 열면 이어서.

D) 인폼 list 카드 정보 위계
   - row height 64px 고정 (이전엔 가변).
   - 1행: 제목 (max 1줄, ellipsis) + 모듈 pill.
   - 2행: lot pill(root + fab) + 상태 pill + 작성자(이름) · 시간(상대시간 "5분 전").
   - hover/focus 시 우측에 ✉️·💬·📎 카운트 mini-icons.
   - 상태 컬러 — received(파랑), in_progress(주황), completed(초록). pill 배경 옅게.

E) 산만함 제거 chore
   - 기존에 같은 화면에 무조건 보이던 폼/모달들 — 다음 패턴으로 정리:
     * Admin 페이지 카탈로그/모듈순서/카테고리 편집은 PageGear(톱니) 안으로 이동.
     * 사진 / 파일 업로드는 detail 의 "첨부" 탭 안으로 한정.
     * 댓글 추가 box 는 "댓글" 탭 안으로 한정.
   - 폰트 14, 카드 padding 12, border-radius 10, spacing 16. 다른 페이지(SplitTable/Dashboard)와 통일.

F) 신규/보강 endpoint
   - GET /api/informs/modules/summary → 모듈별 received/completed/in_progress/pending 카운트(최근 30일 default, ?days 옵션).
   - 다른 endpoint 추가 필요시 backend/routers/informs.py 안에서 호환 추가. 기존 시그니처 변경 X.

G) 회귀 케이스 (반드시 유지)
   - 모듈 wise 메일 자동 수신/제목/본문 (task #1, /modules/recipients, /modules/knob-map)
   - 메일 SplitTable 캡처 layout(첫 cell 라벨만, wafer chunk 통합, overflow-x:auto wrapper)
   - holistic 인폼 등록(POST /api/informs/), 댓글(POST /api/informs/{id}/comments), 이력(GET /api/informs/{id}/history)
   - 메일 발송 throttle(쿨다운 30s + 인폼 burst 10분 5건 + 유저 글로벌 10분 30건)
   - 인폼 module 권한(/api/informs/admin/inform-user-modules — admin 만 편집)
   - 일반 유저 권한 — task #4 매트릭스 정합성 그대로(자기 인폼은 수정/삭제 OK, 남의 것은 admin 만)
