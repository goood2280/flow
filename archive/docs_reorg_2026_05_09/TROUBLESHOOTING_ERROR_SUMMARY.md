# 에러 로그 트러블슈팅 요약

요청된 4개 로그에 대한 짧은 원인 추정과 권장 조치입니다.

## 1) ORA-01461 (updateInputHistory, LONG 컬럼 4000+ 문자)

- 증상
  - `updateInputHistory` 처리 중 `ORA-01461: can only bind a LONG value for insert into a LONG column` 유사 오류 발생
  - 입력 문자열이 4000자 이상이거나 바인딩 방식이 LONG 컬럼과 맞지 않음
- 근본 원인
  - Oracle LONG/VARCHAR2 타입 제약 또는 바인딩 방식 불일치
  - LONG 타입은 구버전 구조로 대용량 문자열 처리/인덱싱/예측성이 낮고, 다국어(UTF-8)일수록 바이트/문자 길이 계산이 달라 제한 초과
- 즉시 조치
  - `updateInputHistory` 입력값 길이 사전 검증(예: 3800자 제한) 및 초과분 저장 정책(요약/분할/트렁케이트) 적용
  - 컬럼 스키마 확인: 실제 대상 타입이 `LONG`인지 `CLOB`인지 점검
- 권장 수정
  - DB 스키마를 `LONG`에서 `CLOB`로 마이그레이션하고 애플리케이션 바인딩을 CLOB 방식으로 변경
  - 마이그레이션 계획: 기존 값 백업 → 타입 변경/재배치 → 애플리케이션 동시 배포

## 2) Mendix `NoClassDefFoundError: org/osgi/service/event/EventHandler`

- 증상
  - 런타임 시작/배포 직후 특정 커스텀 모듈 로딩 시 클래스 미발견 예외 발생
- 근본 원인
  - Mendix 런타임 핵심 모듈(OSGi 패키지)과 커스텀 JAR/라이브러리의 버전 불일치
  - 중복 번들 또는 잘못된 범위로 인한 클래스 가시성 누락
- 즉시 조치
  - 동일 환경에서 동작한 Mendix 런타임 버전과 확장 모듈 버전 매칭 확인
  - 배포 번들 캐시 정리 후 재배포(`deployment`, `model`/`cache` 정리)
- 권장 수정
  - `EventHandler`를 요구하는 모듈/커스텀 라이브러리의 Mendix 호환 버전으로 교체
  - 불필요한 OSGi 번들을 제거하고 의존성 정리(의존 트리 정합성 체크)

## 3) Mendix `IOException: Unable to establish loopback connection` (Jetty)

- 증상
  - Jetty가 로컬 루프백(127.0.0.1/localhost)로 연결을 시도하다 실패
- 근본 원인
  - 로컬 호출 대상 포트 미기동 또는 바인딩 충돌
  - 호스트/포트/프로토콜(S/HTTP) 불일치 또는 방화벽/보안 정책으로 localhost 연결 차단
  - 컨테이너 네트워크 설정이 localhost 대신 잘못된 인터페이스로 설정
- 즉시 조치
  - 같은 머신에서 `curl http://127.0.0.1:<port>` 또는 `https://127.0.0.1:<port>`로 직접 연결 확인
  - Jetty 바인딩 주소를 명시(예: `127.0.0.1`)하고 포트 충돌 확인
- 권장 수정
  - 운영환경에서는 localhost 정책 통일: DNS/프로토콜/포트를 환경 변수로 고정 후 배포
  - 방화벽 예외 및 네트워크 인터페이스 정책 정리
  - 필요 시 AMHS/프록시 계층 설정 제거하여 내부 자기 호출 경로 단순화

## 4) FDC RF3/RF4 Fault, FOUP SOP 이슈

- 증상
  - RF3/RF4 fault signal 반복, FOUP SOP 진행이 멈추거나 반송/교체 동작 반복
- 근본 원인
  - FDC 신호(이벤트 코드)와 장비 레시피/FOUP 상태 머신 간 매핑 불일치
  - FOUP ID, 클램프/도어/진공/센서 상태가 SOP 단계와 동기화되지 않음
  - AMHS/SECS-GEM 인터페이스 타임아웃 또는 이벤트 중복/누락
- 즉시 조치
  - RF3/RF4 발생 시점의 장비/PLC 로그, FDC 이벤트 타임라인, FOUP SOP 단계 로그를 1:1 동기화해 비교
  - FOUP 상태 초기화 및 세이프 인터록 해제(운영 규정 범위 내)로 라인 동기화 상태 복구
- 권장 수정
  - FDC 매핑 테이블 재검증(RF 코드 정의/오류 임계치/릴레이션 룰)
  - SOP 스텝별 게이트 조건과 FOUP 센서 조건을 정합적으로 재정의
  - 중복 이벤트 디바운스/재시도 가드 적용
  - 정기적으로 장비/AMHS 소프트웨어 버전과 통신 스키마(`S2F41`/`S6F11` 등) 호환성 점검

## 공통 대응 패턴

- 장애는 원인 파악을 위해 타임라인 기준 로그를 `시간순-서비스-모듈` 단위로 병합
- 조치 전/후 `재현 조건`, `영향 범위`, `롤백 포인트`를 기록해 RCA 보고서에 남김
- 장기적으로는 임계치, 데이터 크기 제한, 네트워크 정책, 신호맵핑을 환경 설정으로 추적 가능하게 분리
